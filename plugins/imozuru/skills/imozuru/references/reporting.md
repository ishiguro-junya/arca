# レポート作成

調査の停止理由が記録できたら、次の成果物を順に作る。
実行方法は [tools.md](tools.md) を使う。
引用は利用条件と実行環境の引用上限を守り、必要な短さにする。

## 抜き書き

`extracts.json` の各論点へ、原文からそのまま切り出した引用を対応付ける。
ファイル名は `sources/` からの相対パス、行番号は1始まり。
言い換え、字幕の修正、推測した文の補完を引用へ混ぜない。
省略は `…` で示せば、区切りごとに原文内の順序が照合される。

```json
{
  "title": "調査の題",
  "question": "調べた問い",
  "stopped": "論点充足など、実際の終了理由",
  "claims": [{
    "claim": "論点",
    "status": "根拠あり",
    "note": "資料の範囲や不足についての短い注記",
    "quotes": [{
      "file": "author-year-title.md",
      "line": 12,
      "end": 13,
      "text": "原文の指定行からの引用",
      "ja": "必要な場合の日本語訳",
      "mark": "〔本人〕測定あり"
    }]
  }],
  "disagreements": [],
  "unreached": ["届かなかった資料"]
}
```

状態は `根拠あり`・`一部のみ`・`根拠なし` を使う。
`end`・`ja`・`mark`・`note` は必要な場合に付ける。
元ページの URL は `map.md` の原文の表または成功した取得ログから自動で付く。
両方にない場合だけ引用に `url` を指定できる。
食い違いは `disagreements` の `topic` と `quotes` に置き、各引用に `who` を添える。
完全な架空の例はプラグイン内の [extracts.json](../../../examples/demo/extracts.json) を参照できる。

`report.py <topic_dir>` で照合して `report.html` を作る。
照合に失敗したら原文と行番号を読み直し、正しい抜き書きへ直して再実行する。
引用を原文に合わせるために原文そのものを書き換えない。

## 詳細レポート

`digest.json` に読み手の異なる3編を作る。

- `lv1`：前提知識がない人向けに、何が起きているかと用語の意味。
- `lv2`：近い分野を知っている人向けに、仕組み・数値・条件。
- `lv3`：専門家向けに、通説の修正・未決着の点・手法の比較・出典の食い違い。

全編へ同じ説明を言い換えて置かず、読み手に必要な内容を変える。
解説の1文ごとに原文の引用を1つ以上付ける。
根拠がない主張は書かず、調べていない点・資料不足は `unresolved` に置く。

```text
{
  "title", "question", "stopped",
  "claims": [{"claim", "status"}],
  "levels": {"lv1": 編, "lv2": 編, "lv3": 編},
  "people_places": [文],
  "unresolved": ["未解決の論点"]
}
編 = {
  "summary": [文],
  "terms": [{"term", "sentences": [文]}],
  "answers": [{"claim", "sentences": [文]}],
  "quiz": [{"q", "answer": [文]}]
}
文 = {"text", "quotes": [{"file", "line", "end"?, "text"}]}
```

各編に要旨・用語・論点への回答を置き、根拠がある場合は理解を確かめる問いを2〜3問付ける。
`people_places` に人物と媒体の根拠をまとめる。
`digest.py <topic_dir>` で引用を照合し、`digest.html` を作る。
検索・取得の記録はログから自動で組まれるため、見栄えのために架空の記録を足さない。
引用の存在を照合できても主張の含意までは判定できないため、原文が述べていない内容が混ざらないか自分で確かめる。

## ダッシュボードと引き渡し

`dashboard.py <research_dir>` で全トピックの `index.html` を更新する。
ユーザーが閲覧を求めていてファイル表示機能があれば、生成した HTML をその機能で開く。
ローカルサーバーや外部公開は静的 HTML の生成と別の操作として扱う。
配信・スマートフォン利用・継続起動の依頼がある場合だけ、[tools.md](tools.md) の配信手順を使う。

最終応答にはレポートとダッシュボードの絶対パス、停止理由、論点ごとの原文の行、未到達の資料を示す。
優先して読む原文を2〜4本選び、読む箇所と元 URL を添える。
