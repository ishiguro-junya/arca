# RSS の新着確認

「新着」「今週の記事」「imozuru watch」の依頼で使う。
1回だけの依頼は1回の取得で終え、定期ジョブや常駐プロセスを登録しない。

1. 指定された話題の `map.md` を読む。
   なければ公式ブログ・GitHub releases などの実在する媒体を確認し、問い・媒体・人の最小限の地図を作る。
   媒体の見当がつかない分野では [research.md](research.md) の0周目だけを先に行う。
2. `watch.py add <topic_dir> <url>` でフィードを確かめて登録する。
   Qiita・Zenn のタグやユーザー、note、Reddit、YouTube、RSS ブログ、arXiv の検索などに対応する。
   RSS の URL を推測しただけで成功とせず、実行結果を確認する。
3. `watch.py check <topic_dir>` で新着を取る。
   初回は直近14日が既定で、依頼期間がある場合は `--days N` を指定する。
   過去の既読記録を無視して期間を広げ直す場合は `--fresh` を使う。
4. 題名・日付・媒体・URL と、許された範囲の原文の短い冒頭を示す。
   本文を読まずに内容や評価を付けない。
   件数を絞った場合は条件と `watch/` の全結果ファイルを示す。
   新着がなかった媒体の最新記事を、新着と区別する。
5. ユーザーが選んだ記事か既存論点に関わる記事だけを `fetch.py` で取得し、地図に追加する。
   新しい人物や媒体が繰り返し現れたら、次の調査の手がかりに残す。

RSS がない媒体、取得に失敗した媒体、フィードが止まっている可能性を区別する。
確認時刻と期間はユーザーのタイムゾーンで説明し、記事の日付から未提示の時刻を作らない。
定期的な監視を明示依頼された場合は Codex の利用可能な自動化機能を使う。
同じ状態では通知せず、新着・失敗・ユーザーの対応が必要になった場合に通知する。
自動化機能が使えなければ未設定と報告する。
