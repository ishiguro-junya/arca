# 調査手順

## 0. 問いと論点

`map.md` に問いと3〜6個の論点を書く。
最初の論点は「この分野の知見はどこに集まっているか」にする。
少なくとも1つには依頼の対象と条件をそのまま含め、半分以上は効果・限界・不足など原文を読まないと答えられない問いにする。
実践のコツを探す場合は、元になった原典・研究の有無も論点に含める。
問いが変われば論点を更新し、理由を `log.md` に残す。
記録の書式は [records.md](records.md) を使う。

## 1. 地図を作る（0周目）

同じ問いを異なる2つの検索方針で探す。
英語と日本語、または用語検索と総説・教科書探しなどに分ける。
各方針で次を集める。

- 用語と、その用語が現れる URL。
- 人物の所属・代表作。
- 知見が集まる学会・雑誌・個人媒体・リポジトリ。
- 定番の資料の題名・著者・年・公開 URL。
- 見つけたもの、探したが見つからなかったもの、未探索のもの。

媒体は固定の一覧で決めず、その分野の人がどこで発信しているかを探す。
用語が分からなければ事典・教科書・講義資料・総説から原著へ進む。
論文が少ない分野では用語集・入門記事から実践者本人の記録へ進む。
人物の所属、数値、公開状況は原文で確かめるまで「未確認」にする。
検索で返ったヒットは [tools.md](tools.md) の形式で全件記録し、未探索の項目を「次の手がかり」に移す。

## 2. 原文を取得してたどる（1周目以降）

何度も引用される資料、総説、教科書、他の実践者から紹介される人を優先する。

| 動き | 論文 | 個人の発信 |
| --- | --- | --- |
| 後ろへ | 参考文献・`chain.py refs` | 記事内のリンク・参考にした人 |
| 前へ | 被引用・`chain.py cites` | 紹介・引用している記事 |
| 著者で追う | 著者の他の論文・`chain.py author` | 過去記事・チャンネル・投稿一覧 |
| 媒体を通して見る | 中心の学会・雑誌 | タグ・フォーラム・一覧 |
| 近くを眺める | 同じ号・同じ一覧 | 関連記事・再生リスト |
| 言葉で引き直す | 新しく見つけた用語 | 俗称・略語・異なる言語 |

論点に関係する資料を `fetch.py` で保存する。
成功した資料だけを原文の表へ加え、失敗は理由と URL を記録する。
取得した本文を読み、`rg -n` などで行番号と短い引用を確かめ、論点へ対応付ける。
二段組の PDF は左右が同じ行に混ざる場合があるため、行番号だけでなく検索できる短い引用も残す。
動画では行番号と字幕の時刻を併記する。

`chain.py` には `--log <topic_dir> --round <周>` を付ける。
題名・年を確認して DOI を使い、著者は所属や本人の業績一覧と照合する。
引用データが0件でも「存在しない」と判断せず、本文の参考文献や題名検索を使う。
複数の仮説が残る場合は、それぞれの資料を探して比べる。

取得失敗時は次のように進める。

- 有料・ログイン・404では、著者・大学・研究室・公的リポジトリに合法な公開版がないか探す。
- JavaScript 描画や接続方法が原因なら、適切なコネクター・API・CLI を確認してから利用可能なブラウザを使う。
  CAPTCHA の解決が必要ならユーザーへ引き継ぐ。
- 本当に短い資料は表示内容を確認し、短い資料であることを記して保存できる。
  エラーページを短い原文として採用しない。
- 代替取得でも本文・出典・文字化け・アクセス制限の画面を確認し、取得方法と結果を `fetch-log.jsonl` に残す。
  コネクターが返した抜粋を全文と表現しない。

## 3. 周の終了と停止

0周目は地図作り。
1周は「原文を保存し、その原文から参考文献・被引用・著者のどれかを少なくとも1回たどる」まで。
1周目が終わる前には、ユーザー指定の期限・中断を除いて停止しない。

各周で次の停止条件を判定し、理由を `log.md` に書く。

- 論点充足：すべての論点に原文のファイル・行・短い引用が付いた。
- 情報飽和：同じ問いを異なる2方針で探した結果の7割以上が既知で、新しい用語もほぼない。
  重複を除いた人物・資料の件数で分子と分母を記録する。
  7割は上流の経験的な目安で、網羅性の保証ではない。
- 周回上限：1周目から4周を終えた。
  未解決の論点と理由を記す。
- 取得不可：残る論点の資料がすべて有料・ログイン・確認画面の先にあり、合法な公開版も取れなかった。
- 指定上限：依頼の時間・回数・予算に達した。
  論点の充足数と探索の進み具合を記す。

別仮説の結果同士は飽和の比較に使わない。
検索結果があっても保存・確認できた関連原文が0件なら空振りとし、その周では飽和を判定しない。
親が自分で見つけた資料も既知の一覧に含める。
分担した検索役は全員の完了を待ち、使わず中断した検索も理由とともに記録する。
続ける場合は次の手がかりを2〜4個選び、次周へ進む。
終了したら [reporting.md](reporting.md) へ進む。
